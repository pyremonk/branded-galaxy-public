# Resource Management

## Overview

Resource Management is the economic foundation of Branded Galaxy, governing how factions accumulate, store, and spend four distinct resource types to fuel their strategic ambitions. Resources flow from controlled systems to faction pools each turn, modified by loyalty, facilities, faction bonuses, and special locations. Players must balance resource generation, manage storage caps, and make strategic spending decisions across military expansion, construction, research, and diplomatic operations.

The four resource types are:
- **Credits** - Universal currency for purchasing military units, buildings, and services
- **Materials** - Industrial resources required for construction and manufacturing
- **Recruits** - Population pool for training military personnel and recruiting characters
- **Influence** - Political and diplomatic capital for missions, treaties, and covert operations

## Requirements

### FR-RM-001: Resource Type Definitions
- System shall track four distinct resource types per faction
- **Credits**:
  - Primary economic resource
  - Used for: Ship purchases, building construction, character recruitment, emergency actions
  - Generated by: All populated systems, trade hubs (bonus), economic facilities
  - Base production formula: `population × 10`
- **Materials**:
  - Industrial manufacturing resource  
  - Used for: Ship construction, building construction, facility upgrades, repairs
  - Generated by: All populated systems, manufacturing centers (bonus), resource extractors
  - Base production formula: `population × 5`
- **Recruits**:
  - Organic population available for military service
  - Used for: Training fleet crews, recruiting characters, garrison troops
  - Generated by: All populated systems, training facilities, high-loyalty systems
  - Base production formula: `population × 2`
- **Influence**:
  - Political and diplomatic power
  - Used for: Diplomatic missions, espionage, sabotage, propaganda, tech research
  - Generated by: System loyalty levels, diplomatic facilities, special events
  - Base production formula: `(loyaltyValue - 50) / 10` (can be negative)

### FR-RM-002: Resource Generation Per Turn
- Resources shall accumulate each turn during the Resolution Phase
- Resource generation formula per system:
  ```
  ResourceTotal = (BaseProduction × LoyaltyModifier × FactionBonus × SpecialLocationBonus × FacilityBonus)
  ```
- **Base Production**: Defined in FR-RM-001 (population-based)
- **Loyalty Modifier**: 
  - Loyalty 90-100: 1.5× production (enthusiastic support)
  - Loyalty 70-89: 1.2× production (solid support)
  - Loyalty 50-69: 1.0× production (neutral baseline)
  - Loyalty 30-49: 0.7× production (reluctant cooperation)
  - Loyalty 10-29: 0.4× production (minimal cooperation)
  - Loyalty 0-9: 0.1× production (nearly rebellious)
- **Faction Bonus**: Multiplier from faction passive abilities (e.g., Brand Authority +15% credits)
- **Special Location Bonus**: Bonus from system's special type (see FR-RM-003)
- **Facility Bonus**: Additive/multiplicative bonuses from built facilities (Phase 1C)
- All resources round down to nearest integer

### FR-RM-003: Special Location Resource Bonuses
- Special system types shall provide resource production bonuses:
  - **Manufacturing Center**: +50% materials production
  - **Research Facility**: +30% influence production, -10% research costs
  - **Trade Hub**: +40% credits production
  - **Strategic Chokepoint**: +20% influence (strategic value), +10% defense
- Bonuses shall stack multiplicatively with faction bonuses
- Bonuses shall apply automatically when system is controlled (loyalty ≥ 51)
- Bonus values shall be configurable in JSON data files

### FR-RM-004: Faction Resource Pools
- Each faction shall maintain global resource pool (separate from system production)
- Resources flow: System Production → Faction Pool → Spending
- Faction pool updated each turn: `newTotal = currentTotal + turnProduction - turnSpending`
- Resource pools start with faction-specific values (see Faction Identity spec):
  - Brand Authority: 2,000 credits, 1,500 materials, 500 recruits, 300 influence
  - The Union: 1,000 credits, 800 materials, 600 recruits, 500 influence
  - The Autoforge: 1,500 credits, 3,000 materials, 200 recruits, 200 influence
- Resource pools persist across save/load operations
- Negative resources not allowed (cannot go into debt)

### FR-RM-005: Resource Storage Caps
- Each resource type shall have maximum storage capacity
- Default storage caps:
  - Credits: 100,000
  - Materials: 50,000
  - Recruits: 10,000
  - Influence: 5,000
- Resources exceeding cap are lost (wasted production)
- Storage caps shall be upgradeable via technology (Phase 1B: +20% per tech tier)
- UI shall warn when resource pool reaches 90% of cap
- Storage cap increase formula: `cap × (1 + techBonus + facilityBonus)`

### FR-RM-006: Resource Spending - Ship Construction
- Building ships shall consume resources:
  - **Fighter**: 50 credits, 30 materials
  - **Corvette**: 100 credits, 60 materials, 5 recruits
  - **Cruiser**: 250 credits, 150 materials, 15 recruits
  - **Capital Ship**: 800 credits, 500 materials, 50 recruits
- Construction requires shipyard facility (Phase 1C)
- Resources deducted when construction begins
- Partial refund (75%) if construction cancelled
- Construction time: 1-5 turns depending on ship type and faction bonuses

### FR-RM-007: Resource Spending - Building Construction
- Constructing facilities shall consume resources:
  - **Shipyard**: 500 credits, 300 materials (enables ship construction)
  - **Research Lab**: 400 credits, 200 materials (speeds research +25%)
  - **Training Facility**: 300 credits, 150 materials, 20 recruits (increases recruit generation +30%)
  - **Defense Platform**: 600 credits, 400 materials (provides orbital defense)
  - **Resource Extractor**: 250 credits, 150 materials (increases materials +20%)
  - **Trade Center**: 350 credits, 100 materials (increases credits +25%)
- Only one facility type per system (Phase 1A limitation, relaxed in 1C)
- Construction time: 2-6 turns depending on facility type
- Resources deducted when construction begins
- Partial refund (75%) if construction cancelled before half complete, 0% after

### FR-RM-008: Resource Spending - Technology Research
- Researching technologies shall consume resources (Phase 1B):
  - **Tier 1 Techs**: 200-400 credits, 50-100 influence
  - **Tier 2 Techs**: 500-800 credits, 100-200 influence
  - **Tier 3 Techs**: 1,000-1,500 credits, 200-350 influence
  - **Tier 4 Techs**: 2,000-3,000 credits, 400-600 influence
  - **Tier 5 Techs**: 4,000-6,000 credits, 800-1,200 influence
- Research costs deducted when research begins
- Research cannot be cancelled (resources non-refundable)
- Faction modifiers apply (e.g., Brand Authority +10% cost, Autoforge -20% cost)

### FR-RM-009: Resource Spending - Missions
- Executing missions shall consume influence and/or credits (Phase 1B):
  - **Diplomacy Mission**: 50 influence, 100 credits
  - **Espionage Mission**: 75 influence
  - **Sabotage Mission**: 100 influence, 50 credits
  - **Recruitment Mission**: 150 credits, 25 influence
  - **Assassination Mission**: 200 influence, 300 credits (high risk)
- Resources deducted when mission launches
- Failed missions: No refund
  - Successful missions: May yield resource rewards (credits, intel)
- Faction modifiers apply (e.g., Autoforge 2× influence cost for diplomacy)

### FR-RM-010: Resource Spending - Emergency Actions
- Players may execute emergency actions at premium cost:
  - **Rush Construction**: Pay 2× remaining cost to complete facility/ship immediately
  - **Emergency Recruitment**: Pay 3× normal cost to recruit character instantly
  - **Forced Loyalty**: Spend 500 influence + 1,000 credits to set system loyalty to 75 (temporary)
- Emergency actions bypass normal turn limits
- Emergency actions have cooldown period (cannot spam)
- Emergency actions may have narrative/diplomatic consequences

### FR-RM-011: Resource Display - HUD
- Main game HUD shall display current faction resource totals prominently
- Resource display format:
  ```
  💰 Credits: 2,450 / 100,000
  ⚙️ Materials: 1,820 / 50,000
  👥 Recruits: 340 / 10,000
  ⭐ Influence: 215 / 5,000
  ```
- Color coding:
  - Green: Resource > 50% of cap
  - Yellow: Resource 25-50% of cap
  - Orange: Resource 10-25% of cap
  - Red: Resource < 10% of cap or near cap (>90%)
- Per-turn generation rate displayed: `+450/turn` below resource total
- Tooltip on hover shows resource breakdown

### FR-RM-012: Resource Display - Detailed Breakdown
- System shall provide detailed resource breakdown screen accessible from HUD
- Breakdown shows:
  - **Total Production This Turn**: Sum of all system production
  - **Per-System Breakdown**: List each controlled system with its production
  - **Modifiers Applied**: Loyalty, faction bonuses, facility bonuses, special locations
  - **Spending This Turn**: List of all expenditures (construction, missions, research)
  - **Net Change**: `+/- X` resources gained/lost this turn
  - **Projected Next Turn**: Estimated production for next turn
- Breakdown updates in real-time as player queues spending actions
- Export breakdown as CSV/JSON for analysis (optional feature)

### FR-RM-013: Resource Trends and Forecasting
- System shall track resource trends over last 10 turns
- Trend indicators display:
  - ↑ Rising (increasing production trend)
  - ↓ Falling (decreasing production trend)
  - → Stable (no significant change)
- Forecast system predicts resources 5 turns ahead based on current trajectory
- Warnings displayed if forecast shows resource depletion or cap overflow
- Trend graph accessible via resource detail screen (line chart showing 10-turn history)

### FR-RM-014: Resource Transactions and Logging
- All resource transactions shall be logged for player reference
- Transaction log includes:
  - Turn number
  - Resource type and amount
  - Transaction type (production, spending, adjustment)
  - Source/destination (system, building, mission)
  - Timestamp
- Transaction log accessible via UI panel
- Log filterable by resource type, transaction type, turn range
- Log exportable for debugging/analysis

### FR-RM-015: Resource Multiplayer Considerations
- Each faction in multiplayer shall have independent resource pools
- Resource transactions cannot cross faction boundaries (no trading in Phase 1A)
- Resource states must synchronize across clients in network multiplayer
- Resource cheating prevention: Server validates all transactions
- Resource state checksum: Validate resource counts match across clients each turn

### FR-RM-016: Resource Persistence
- Resource state shall serialize to JSON for save/load
- Serialized data includes:
  - Current resource totals
  - Resource caps
  - Turn-by-turn production history (last 10 turns)
  - Queued spending (reserved resources)
  - Transaction log
- Deserialization shall restore exact resource state
- Save file shall include resource checksum for validation

## Constraints

### CN-RM-001: Performance
- Resource calculations for all factions and systems must complete in < 50ms per turn
- Resource generation for 100+ systems shall not cause frame drops
- Resource UI updates shall complete in < 10ms (smooth 60 FPS)
- Transaction log queries shall complete in < 100ms

### CN-RM-002: Balance
- Total galaxy resource production shall scale with galaxy size:
  - Small galaxy (24-48 systems): ~5,000-10,000 credits/turn
  - Medium galaxy (40-70 systems): ~10,000-20,000 credits/turn
  - Large galaxy (64-120 systems): ~20,000-40,000 credits/turn
- Starting resources shall sustain faction for 5-10 turns without additional production
- Resource caps shall allow storage of 10-20 turns of average production
- No single resource type shall bottleneck gameplay excessively

### CN-RM-003: Data Structure
- Resource values shall use integer types (no floating point to avoid precision errors)
- Resource modifiers shall be calculated with floating point, then rounded to integer
- Resource state shall be part of faction state object
- Resource generation logic shall be data-driven (configurable in JSON)

### CN-RM-004: Integration Points
- Resource management must integrate with:
  - **Faction Identity**: Faction bonuses modify resource generation
  - **Galaxy Generation**: System production potential comes from population
  - **System Loyalty**: Loyalty modifies resource production efficiency
  - **Turn System**: Resources regenerate each turn
  - **Technology System**: Research consumes influence/credits, provides production bonuses
  - **Fleet Management**: Ship construction consumes credits/materials/recruits
  - **Base Construction**: Facility construction consumes credits/materials
  - **Mission System**: Missions consume influence/credits
  - **Data Bridge**: Resource state persists via data bridge

### CN-RM-005: UI/UX
- Resource display shall be visible at all times (persistent HUD)
- Resource transactions shall provide immediate visual feedback (number pop-ups, animations)
- Insufficient resources shall prevent action execution with clear error message
- Resource warnings (near cap, near depletion) shall be non-intrusive but noticeable

### CN-RM-006: Technical Limitations
- Pure JavaScript implementation (no TypeScript)
- ES module structure with `.js` extensions
- Compatible with Vite build system
- React components for resource UI panels
- Phaser integration for in-game resource displays and animations

### Resource Generation Algorithm

```javascript
// Calculate total resource production for a faction this turn
function calculateFactionProduction(faction, galaxy) {
  const production = { credits: 0, materials: 0, recruits: 0, influence: 0 };
  
  // Iterate through all systems controlled by faction
  const controlledSystems = galaxy.systems.filter(s => s.loyalty === faction.id);
  
  for (const system of controlledSystems) {
    const systemProduction = calculateSystemProduction(system, faction);
    production.credits += systemProduction.credits;
    production.materials += systemProduction.materials;
    production.recruits += systemProduction.recruits;
    production.influence += systemProduction.influence;
  }
  
  return production;
}

function calculateSystemProduction(system, faction) {
  // Base production
  const baseCredits = system.population * 10;
  const baseMaterials = system.population * 5;
  const baseRecruits = system.population * 2;
  const baseInfluence = (system.loyaltyValue - 50) / 10; // Can be negative
  
  // Loyalty modifier (0.1× to 1.5×)
  const loyaltyMod = getLoyaltyModifier(system.loyaltyValue);
  
  // Faction bonuses
  const factionCreditBonus = faction.bonuses.creditIncome || 1.0;
  const factionMaterialBonus = faction.bonuses.materialProduction || 1.0;
  const factionRecruitBonus = faction.bonuses.recruitGeneration || 1.0;
  
  // Special location bonuses
  let specialCreditBonus = 1.0;
  let specialMaterialBonus = 1.0;
  let specialInfluenceBonus = 1.0;
  
  if (system.specialType === 'tradeHub') {
    specialCreditBonus = 1.4 * (faction.bonuses.tradeHubBonus || 1.0);
  } else if (system.specialType === 'manufacturingCenter') {
    specialMaterialBonus = 1.5;
  } else if (system.specialType === 'researchFacility') {
    specialInfluenceBonus = 1.3;
  } else if (system.specialType === 'strategicChokepoint') {
    specialInfluenceBonus = 1.2;
  }
  
  // Facility bonuses (Phase 1C)
  const facilityCreditBonus = calculateFacilityBonus(system, 'credits');
  const facilityMaterialBonus = calculateFacilityBonus(system, 'materials');
  const facilityRecruitBonus = calculateFacilityBonus(system, 'recruits');
  
  // Final calculation (all bonuses stack multiplicatively)
  return {
    credits: Math.floor(
      baseCredits * loyaltyMod * factionCreditBonus * 
      specialCreditBonus * facilityCreditBonus
    ),
    materials: Math.floor(
      baseMaterials * loyaltyMod * factionMaterialBonus * 
      specialMaterialBonus * facilityMaterialBonus
    ),
    recruits: Math.floor(
      baseRecruits * loyaltyMod * factionRecruitBonus * facilityRecruitBonus
    ),
    influence: Math.floor(
      baseInfluence * specialInfluenceBonus
    )
  };
}

function getLoyaltyModifier(loyalty) {
  if (loyalty >= 90) return 1.5;
  if (loyalty >= 70) return 1.2;
  if (loyalty >= 50) return 1.0;
  if (loyalty >= 30) return 0.7;
  if (loyalty >= 10) return 0.4;
  return 0.1;
}
```

### Resource Spending Example

```javascript
// Attempt to spend resources (returns success boolean)
function spendResources(faction, costs) {
  // Check if faction has sufficient resources
  for (const [resource, cost] of Object.entries(costs)) {
    if (faction.resources[resource] < cost) {
      return {
        success: false,
        error: `Insufficient ${resource}: need ${cost}, have ${faction.resources[resource]}`
      };
    }
  }
  
  // Deduct resources
  for (const [resource, cost] of Object.entries(costs)) {
    faction.resources[resource] -= cost;
    
    // Log transaction
    faction.transactionLog.push({
      turn: currentTurn,
      timestamp: Date.now(),
      type: 'spending',
      resource: resource,
      amount: -cost,
      source: 'construction' // or 'mission', 'research', etc.
    });
  }
  
  return { success: true };
}

// Example: Build a cruiser
const cruiserCost = { credits: 250, materials: 150, recruits: 15 };
const result = spendResources(faction, cruiserCost);
if (!result.success) {
  showError(result.error);
}
```

   - *Recommendation*: Validate via playtesting; influence should limit mission spam but not bottleneck diplomacy

3. **Recruit Bottleneck**: Will recruits become bottleneck for Autoforge faction?
   - *Recommendation*: Autoforge bonuses offset with automation (less recruit dependence for ships)

4. **Resource Caps**: Should caps scale with number of controlled systems or remain fixed?
   - *Recommendation*: Fixed caps initially (Phase 1A), add scaling via tech (Phase 1B)

5. **Emergency Actions**: Are emergency action costs balanced (2-3× normal cost)?
   - *Recommendation*: Playtest; should be viable lifeline but not optimal strategy

6. **Resource Display**: HUD placement - always visible or toggleable?
   - *Recommendation*: Always visible (critical info), but compact design to avoid clutter
